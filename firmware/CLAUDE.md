# Firmware development

## Target and dependencies

Production target: `blikachu_pocket/bl618m05q2i` (v2.0 hardware).
Zephyr is pinned to **v4.5.0** in `west.yml`. SDK 1.0.1 supports the BL618
T-Head ISA extensions. Use the workspace `.venv` and in-tree `deps/zephyr`.

Hardware is in `../hardware/`. Trust PCB pad nets over the Eagle-imported
schematic. The BL618G0 devkit is the reference for differential testing; its
flash and button/display wiring differ from the production board.

## Build, update and recovery

Use only `build/`; do not create additional build directories.

```bash
./build.sh
./build.sh clean
./build.sh flash
```

Default board is BL618. `flash` uses USB DFU if available. The payload is
`build/zephyr/zephyr.dfu.bin` (BFNP boot header + application, generated by
`tools/bflb_whole_img.py`). Keep power connected until installation and the
subsequent reboot complete. Download completion is NOT installation completion.

```bash
dfu-util -d 2e8a:000a -D build/zephyr/zephyr.dfu.bin
```

Recovery: hold BOOT, reset, release BOOT. BootROM USB identifies as
`Bouffalo CDC DEMO`. Discover its port each time; USB port names change.

```bash
FLASH_PORT=/dev/cu.usbmodemXXXXX ./build.sh flash
```

The project BootROM flasher verifies the image and automatically resets the
board. USB CDC exposes the shell; UART0/J3 carries logs only. Do not open or
manipulate UART when the user is using it. Check actual devices before asking
the user to press buttons. Build/flash/test is authorized without per-step
confirmation. Do not format storage or erase user ROMs/saves without approval.

## Board

- BL618 AU PLL CPU overclock to 480 MHz; BCLK 80 MHz, WiFi PLL 320 MHz; 4 MiB embedded PSRAM.
  The SPI peripheral clock is independent of the CPU root (160 MHz WiFi PLL output).
  `perfclock` measures CPU cycles against the machine timer and reports clock configuration.
- U3 W25Q512JV: JEDEC `ef4020`, 64 MiB, SF2 GPIO4–9.
- Flash: boot header 0–0x2000; application 0x2000–0x800000;
  LittleFS 0x800000–0x1000000 (8 MiB), mount `/NAND:`;
  contiguous XIP ROM extents 0x1000000–0x4000000 (48 MiB).
  Four-byte addressing and quad-output XIP (`0x6b`, SFDP QE setup) are enabled.
  Flash uses the BCLK source with divider 1, without continuous-read mode.
  The RAM reset hook restores the
  flash to three-byte mode for the BootROM. BootROM programming stays below
  8 MiB in three-byte mode. The project flasher registers the ef4020 profile,
  checks the address-mode status and propagates programming failures.
- ST7789V 240x240 SPI/DMA, visible viewport 240x216; MOSI23, CS24,
  SCLK25, DC26, RESET27, TE20. Backlight GPIO28 uses timer0 soft-PWM.
- Buttons: UP15, LEFT16, DOWN17, RIGHT18, START29, B30, SELECT31, A32.
- Buzzer: GPIO14/PWM0 channel 2. PWM channels share a period, so do not
  move the backlight onto PWM0.
- UART0: TX21/RX22. USB HS has dedicated pins; CDC + DFU composite.
- Charger MCP73871: STAT1=11, STAT2=12, PG=13. Battery sense GPIO10/ADC7.
- LED0 GPIO34 is active-low on the PCB.
- Power latch: U6 74LVC1G80, R40 ties D to inverted Q. GPIO19 must be
  input-only; read high = held. A GPIO33 rising edge toggles the latch.
  Q5 gates both battery and charger-output power to the buck.

## Runtime and update architecture

`main.c` starts storage, USB, boot animation, then the game menu. Shared
application code uses `platform_bl618.c` for hardware services. Display,
libretro frontend, PCM audio, hotkeys, save states, settings, WiFi provisioning,
HTTP ROM manager, remote play and OTA are in `src/`.

`src/bl618/usb_dfu.c` and WiFi OTA (`src/ota.c`) share the 3.5 MiB PSRAM
upload buffer with HTTP uploads. Claims are exclusive. Images must fit the
staging buffer. DFU checks the BFNP header CRC and the application SHA-256,
then `src/bl618/fw_install.c` writes and verifies flash with IRQs locked.
The installer and every flash-unavailable dependency must execute from RAM.
`libgcc_ram.c` supplies division helpers without flash-resident variable-shift
helpers. The installer copies driver dispatch structures into RAM and uses
`reboot.c` for a real BL61x reset (Zephyr's default RISC-V reset is a stub).

An interrupted in-place install is NOT power-fail-safe; recover via BootROM.
LittleFS mounts do not automatically format missing/invalid filesystems.
The hash checks corruption, not image authenticity. There is no signed-image
secure boot or A/B rollback.

## Shell and controls

- `emu list`, `emu run <name|path|index> [frames]`, `emu stop/pause/resume/reset`
- `emu info`, `emu apu`, `emu btn <button> [hold_ms]`
- `emu save [path]`, `emu restore [path]`: core/ROM-specific `.lrstate` files
  under `.saves/`; launches cold-boot and restore separate battery/RTC files.
- `emu vol [0-11]`, `emu mute on/off`, `bright [1-10]`
- `cfg list/get/set/del`: `/NAND:/.blikachu.cfg`
- `mount`, `umount`, `disk`, `romaddr`, `romcrc`, `fs ls /NAND:`
- `mkfs` is destructive; ask before using it.
- `wifi_cred add/list/del`, Zephyr `wifi` commands, WebUI on HTTP port 80.
- `ota apply [path]`: checked whole-flash image, default `/NAND:/update.bin`.
- `resetinfo` first after unexpected resets; saved fault record is in
  `__noinit` RAM and does not survive power loss. Generic reset-cause
  reporting may return zero; do not infer brownout from it.

Hotkeys: SELECT+START quits; SELECT+B saves; SELECT+A restores;
SELECT+UP/DOWN changes volume; SELECT+LEFT/RIGHT changes brightness.
Long START requests power-off.
SELECT is deferred so system chords are not delivered as game input.
SNES uses physical A/B for B/Y, SELECT+A/B for A/X and SELECT+LEFT/RIGHT
for L/R. Save/restore and brightness are available through the shell.

## Scheduling and memory

Priority ladder: shell(4), input(7), LCD push/scale(8), emu(10).
The buzzer consumes resampled PCM from a timer while audible; muted output
does not schedule PWM updates.
Event-driven work must outrank the CPU-saturating emulator. The BL618 watchdog
feeder is cooperative priority 0; timeout 1900 ms, feed every 250 ms.
Long flash operations must pause the watchdog and prevent it being re-armed.

The lower 512 KiB of PSRAM holds firmware buffers; the upper 3.5 MiB is the
exclusive core/update workspace, managed by `src/libretro/workspace.c`.
Its linker overlays are in `src/libretro/memory.ld`; core data/BSS must be
initialized only after claiming the region. Gambatte constructors are kept
out of the boot-time constructor list. Core heap and update staging usage
are not reflected by the linker's static CORE_RAM occupancy.
LittleFS stores the ROM catalogue separately from immutable raw flash
extents. Uploads verify the new extent before atomically publishing its
record. The storage guard covers mapping, workspace acquisition and ROM
mutations while a core borrows XIP bytes.

The libretro frontend selects Gambatte, FCEUmm or Snes9x2005 from the
ROM header/extension. `lrprobe <path> [frames]` exercises core lifecycle,
serialization and runtime memory without display output. `emu info` counts
emulated and completed-display frames independently.
The concurrent display schedule uses short cooperative checkpoints at
core event boundaries while the renderer is waiting for TE or DMA. These
do not change emulated CPU/APU cycles. The renderer compares native pixels
to avoid pushing unchanged strips and clips unchanged letterbox rows.
`emu info` reports completed updates, unchanged frames, strips transferred
and superseded frames. `lrdisplay dma` isolates the core during strip
transfers; Snes9x can skip rendering after a late frame in either schedule.
`lcdbench` measures idle DMA; `lrdmaprobe` profiles a gameplay benchmark
without automatic battery-save writes.
WiFi DMA buffers remain in SRAM. Display DMA alternates two aligned uncached
WRAM buffers of up to 32 rows, each fitting one word-mode DMA block.
Only dirty strips enter the producer/consumer queue; each uses a complete
panel transaction and an 80 MHz SPI request.
The frontend and pixel/audio conversion compile at -O3. SRAM is nearly full: inspect the
linker report before adding stacks or buffers. Never invalidate dirty
D-cache lines without writing them back first.

## Project-owned Zephyr patches

Never edit `deps/` directly. Maintain patches; `build.sh` applies them
idempotently using reverse-apply checks.

- 0001: MSC medium control and eject callback.
- 0003: BL61x USB HS UDC v2, based on the user's local Zephyr driver;
  includes pre-RX-DMA cache writeback/invalidation.
- 0005: default flash SR1/WIP busy polling.
- 0006: SPI TX word-mode DMA, direct WRAM transfers and staged fallback.
- 0012: direction-aware DMA cache maintenance and uncached WRAM handling.
- 0013: FatFs file-sharing locks when reentrant operation is enabled.
- 0008: flash range validation in RAM.
- 0010: return the flash to three-byte mode before BootROM reset.
- 0009: flash deferred-message clear in RAM; with flash logging disabled,
  no XIP diagnostic dispatch is used during an in-place install.
